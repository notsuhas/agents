# Expense sync

Record an expense in Settle Up, Money Lover and Nomad through the existing Upsy connection. One host call handles the account reads, writes and verification.

Requires Bun 1.4 or newer. No package installation is needed. Keep the profile and receipts outside this repository; they contain private account references and spending.

## Input

Save a profile at `~/.config/expense-sync/profile.json` with mode `0600`:

```json
{
  "nomadApp": "your-nomad-app-id",
  "homelabApp": "your-homelab-app-id",
  "trip": "your-nomad-trip-id",
  "group": "Your Settle Up group",
  "event": "your-money-lover-event-id",
  "nomadOtherName": "Other traveller",
  "members": { "me": "Your Settle Up name", "other": "Other Settle Up name" },
  "wallets": {
    "suica": { "name": "Your Suica wallet", "currency": "JPY", "pocket": "your-nomad-prepaid-pocket-id" },
    "card": { "name": "Your card wallet", "currency": "INR" }
  }
}
```

Use one stable receipt ID on every retry. For a bank payment, use its transaction reference. For a fare, include the date, time, route and amount. A receipt file looks like this:

```json
{
  "id": "fare-20261020-2259-route-155",
  "merchant": "Station A → Station B",
  "amount": 155,
  "currency": "JPY",
  "dateTime": "2026-10-20T22:59:00+09:00",
  "wallet": "suica",
  "paidBy": "me",
  "shares": { "me": 155, "other": 0 },
  "category": "travel",
  "moneyloverCategory": "Intercity Travel"
}
```

`paidBy` is `me` or `other`. Shares are explicit amounts, including zero for someone not included. For an INR card, pass the actual INR debit and put the yen receipt in `original: { "amount": 130, "currency": "JPY" }`. No exchange rate is guessed. Optional `note` stays private in the input. Optional `details` is a short purchase description shown in the apps; it defaults to the merchant. `funding: "ho"` excludes the booking from expense apps.

## Commands

```sh
bun scripts/expense-sync/cli.ts plan --input /private/path/receipt.json
bun scripts/expense-sync/cli.ts host --input /private/path/receipt.json
bun test scripts/expense-sync/core.test.ts
```

`plan` validates without account access. `host` emits a JSON bundle for the active tool host. It uses that host’s authenticated Upsy tools; it does not copy OAuth credentials or start another login.

One `functions.exec` call runs the wrapper:

```js
const built = await tools.exec_command({
  cmd: "bun /path/to/backbone/scripts/expense-sync/cli.ts host --input /private/path/receipt.json",
  max_output_tokens: 16000
});
if (built.exit_code !== 0) throw new Error(built.output);
const bundle = JSON.parse(built.output);
const mod = { exports: {} };
new Function("module", "exports", bundle.code)(mod, mod.exports);
text(await mod.exports.run(tools, bundle.profile, bundle.receipt));
```

Evaluate only the bundle generated by this trusted local CLI. Do not evaluate code returned by an account tool. For a standalone terminal integration, `record --input receipt.json --adapter /trusted/path/adapter.ts` accepts a module exporting `read(app, tool, args)` and `call(app, tool, args)` through an already authenticated Upsy client. No standalone OAuth adapter is installed by this helper.

## Behaviour and limits

- Account reads run together; writes run sequentially. Receipt IDs and app row IDs stay in a private `receipt-ledger.json` beside the profile. Visible notes contain purchase details only. Reruns reuse indexed rows or exact descriptions and timestamps; conflicting or ambiguous rows stop the operation. Older visible markers remain readable for migration.
- A provider may commit before a connection fails, and its reads may lag. Host mode writes a private pending journal before mutations and blocks another run after an uncertain result. Read all three apps, resolve any duplicate or missing rows, and remove that receipt's pending flag only after verification. There is no cross-app transaction or rollback. Run the same receipt serially; separate hosts can race because these APIs expose no atomic idempotency key.
- Unequal splits become separate beneficiary entries in Settle Up, one custom split in Nomad, and the user’s expense/lending entries in Money Lover. A personal expense belonging entirely to the other traveller has no Money Lover entry in the user’s wallets.
- Money Lover records the user’s share and the appropriate lending/debt offset. Other-paid entries leave the user’s wallet unchanged. A configured Nomad pocket is used only when the user paid.
- Verification checks each receipt leg before reporting success. Unsupported operations or permission errors remain failures; the wrapper does not retry through another connector.
- This wrapper handles expenses. Cash-to-Suica funding remains a transfer; Nomad’s missing pocket-transfer operation must not be replaced by a fake expense. Existing untagged entries can be reused when their notes contain the same bank/receipt reference and their amounts, participants, wallet, categories and timestamps agree. Entries without that reference need manual review before import.
